# Product Memo：AIIC（AI Interview Coach）面试陪练平台

**版本**：1.0（挑战项目提交版）　**日期**：2026-08-30
**状态**：可公网演示的 MVP（40/40 自动化测试通过；CPU+双 4090 GPU 双主机已部署）

## 0. 一句话与项目亮点

AIIC 是一个把「岗位 JD、个人简历、面试流程、题目与评分标准」串成一条可解释训练路径的 AI 面试陪练平台：用户上传脱敏 JD 和简历后，系统通过 GraphRAG 关联岗位-技能-题目-Rubric，给出可溯源的匹配评分与个性化题目；用户作答后获得引用原句证据的结构化反馈，并被持续追问，直到形成训练报告。

区别于「直接问 ChatGPT」的五个核心优势（均已实现，可在代码与测试中核验）：

1. **可解释且稳定的匹配**：评分按 4 维加权并给出解释与技能缺口；结果以不可变快照持久化（简历/JD 不变则分数不漂移、不重复付费调用），个性化题目强制引用检索到的真实题源，防止模型伪造溯源。
2. **8 种场景各有独立策略与 Rubric**：技术/算法/行为/压力/案例/科研/HR/群面；群面由 2-3 位互补人设的 AI 队友驱动，用户不发言时队友自主推进讨论（节奏可调、可暂停、发言持久化回放）。
3. **证据式反馈闭环**：反馈必须引用用户原回答句子，支持重答/补充（父子 Turn）、锚定证据的连续追问和幂等重放（断网重提不丢输入、不重复评分）。
4. **真实可运行的算法面**：Python 受限沙箱（AST 白名单 + audit hook + 资源限制）跑服务端固定测试，判题结果并入反馈与报告。
5. **工程可信度**：本地双 4090 Qwen 网关 + 第三方强模型 + 确定性规则的三级降级（模型全挂演示不中断）；全部 31 条活动题目带 MIT 来源、许可证、版本与内容哈希；账户数据按服务端会话严格隔离。

## 1. 目标用户与核心痛点

**目标用户**：准备实习、校招或保研面试的本科生与研究生（软件开发、算法、数据、科研方向为主）。他们有 JD、项目经历和零散题库，但缺一条把「岗位要求→个人经历→练习→改进」串起来的路径。

**调研做了什么、发现了什么**：当前证据 = 项目发起人的连续需求输入 + 1 条匿名真实调研记录（R-001）。我们刻意不把单样本包装成统计结论，但 R-001 给出了改变设计的真实信号：

| 发现（R-001 原话要点） | 对产品的含义 |
| --- | --- |
| “第一种是群面和单面” | 一级入口先分群面/单面，而不是笼统的“开始面试” |
| 单面细分简历面/专业面/论文面/实习面/行为面/英文面，一场面试可组合多个环节 | 不能只做一个“技术面”，场景必须策略化、可组合 |
| “一直问我简历问题，把简历上所有可挖掘的都问到” | 需要围绕个人证据持续深挖的追问引擎，而非一次性出题 |
| 群面难找“水平相近且刚好同时有空”的真人 | 群面核心是撮合约束；当前版本先用 AI 队友提供单人可用形态（ADR-009） |
| “自动录屏和自动转写是基础的” | 复盘与证据提取是刚需，媒体链路列入路线图 |

**证据边界（诚实声明）**：仓库中的问卷样例为 `synthetic_mock`，仅用于验证分析流程；扩大访谈（5-8 人）与问卷（20-30 份）列入下一周计划，回填前不得对外宣称“用户调研证明”。

## 2. 产品设计说明

**核心功能（全部 `implemented`，详见 `docs/requirements-traceability.md` FR-01~FR-20）**：

| 功能 | 用户价值 |
| --- | --- |
| 临时工作区 + 无缝注册升级 | 零门槛体验；注册原地升级，档案/训练记录全保留 |
| 简历/JD 上传 → AI 提取 → 人工校对确认 | AI 结果不经确认不成为事实，减少录入又防幻觉 |
| 岗位匹配（评分快照 + 可溯源个性化出题） | 解释“为什么是这个分、缺什么技能、为什么问这道题” |
| 8 场景训练（含 AI 队友群面）+ 证据反馈 + 追问/重答 | 每个场景独立 Rubric；建议可定位、可执行、可再练 |
| Python 算法沙箱 | 思路、复杂度、代码正确性一站验证 |
| 题库（来源/许可证/置信度展示）、收藏、训练报告 | 自主练习与逐轮复盘 |
| Model Router 三级降级 + 成本遥测 | 供应商可换、故障可解释、成本可算 |

**刻意没做的功能与原因**：实时语音/视频/数字人（媒体链路的工程与隐私成本会挤掉核心闭环验证，且 R-001 表明录屏转写价值在复盘而非实时感）；自训练模型（无标注数据支撑）；Kubernetes（双主机 Compose 已满足复现与隔离）；真人群面撮合（等待池/隐私/缺席处理需先做用户研究，先交付 AI 队友形态）；抓取未授权面经（许可与真实性不可控——我们宁可只有 31 道有 MIT 来源的题，也不放一万道来路不明的题）。

## 3. 版本迭代记录（遇到什么问题、怎么改、为什么）

- **V0 → 范围收敛**：最初设想含数字人、语音视频、全场景。问题：一天内交付风险过高。改为文字闭环优先、媒体留接口——先证明“匹配→题目→反馈”的价值假设。
- **全远程 API → 混合模型架构**：成本、延迟与供应商单点不可接受。改为双 4090 本地网关承担抽取/出题，强模型只做复杂评分，统一经 ModelRouter 降级与遥测。
- **抓真实题库 → 来源治理 + 许可转写**：公开面经的版权与“高频”真实性无法证明。改为 MIT 来源转写 + 全字段来源台账，早期合成题软删除留审计。
- **一次性出题 → 证据反馈 + 追问闭环**：发现一次性答案无法告诉用户“哪里不好”。为每场景定义 Rubric，反馈强制引用原句证据，支持 `revision_of` 重答。
- **模型直答代码题 → 受限沙箱**：模型不能替代可信执行。上线 AST 策略 + audit hook + 资源限制的判题沙箱，并明确公网前迁移独立 runner。
- **后期三次实战驱动的加固**（见 `CHANGELOG.md`）：真实部署中发现评分漂移与重复付费 → 引入不可变评分快照（ADR-008）；发现代理超时导致重复提交 → 加入幂等重放与断线自愈；发现群面“没人说话就冷场” → 加入队友自主推进引擎（v8 迁移，`group_messages` 表）。

## 4. 下一步设计（如果再给一周）

- **第 1-2 天 · 真实研究**：完成 5-8 个半结构化访谈 + 20-30 份匿名问卷，主题编码回填本 Memo，校准 P1 优先级（简历深挖模式 vs 可组合单面流程 vs 真人群面等待池）。
- **第 3 天 · 评测集**：5 组脱敏 JD × 5 组背景 × 20-30 题建人工金标准，量化匹配准确率、证据引用率、编造率、追问相关性。
- **第 4 天 · 反馈质量**：Prompt/Rubric 版本化、人工复核界面（标记事实错误/证据缺失/建议不可执行）。
- **第 5 天 · 模型与成本**：用同一评测集对比本地 Qwen、强模型与规则 fallback 的 p50/p95、成本与质量（`model_invocations` 遥测已就绪，见 `docs/performance-test-plan.md`）。
- **第 6 天 · 安全与容量**：独立沙箱 runner、GPU 网关 mTLS、备份恢复演练、25 并发压测。
- **第 7 天 · 用户验证**：≥5 名真实用户完整走一轮，修 Top3 问题，更新全部文档与 Demo。

## 5. AI 工具使用

| 工具/能力 | 使用环节 | 人工责任 |
| --- | --- | --- |
| ChatGPT/Codex 类强模型 | 需求梳理、方案与文档草拟、复杂回答评分、个性化出题 | 核对实现、事实与隐私边界；schema 校验 + 规则兜底 |
| 本地 Qwen3-32B（vLLM，双 4090） | JD/简历抽取、轻量出题、结构化 fallback | 校验 JSON 与显存/延迟 |
| Claude Code / Codex 编码代理 | 代码实现、测试编写、文档补全与 QA 审计 | 全部提交人工审阅，40 个回归测试守护 |
| GitHub API / 网页核验 | 题库来源与 MIT 许可核验 | 判断可转写/可再分发，登记来源台账 |

**原则**：AI 不是事实来源。AI 生成的用户经历、来源许可、评测结论必须人工核验；所有 AI 中间结果（简历解析、评分）要么经用户确认、要么经 schema 校验 + 确定性兜底才进入系统。

## 6. 成功标准与已知未解决问题

**成功标准**：≥5 名真实用户完成一轮训练且 4/5 可独立完成；3/5 认为反馈比通用 ChatGPT 更具体；每条反馈含 ≥1 条原句证据与可执行改进；模型失败/超时/重答均不丢输入（最后一条已由自动化测试保证）。

**未解决问题**：真实用户最看重的场景待访谈验证；反馈质量缺人工金标准；强模型额度与数据保留依赖服务条款；沙箱为挑战版隔离，公网开放前须迁移独立 runner；账户缺邮件验证/找回密码/OAuth。
