# AIIC 架构决策记录（ADR）

## ADR-001：采用 Docker Compose 双主机部署

- **状态**：accepted
- **背景**：业务 API、数据库和前端需要稳定复现；本地模型使用远程双 RTX 4090。
- **决策**：CPU 业务服务器和 GPU 模型服务器分别使用 Compose；前端通过 Nginx 代理 backend；GPU 网关只允许私网访问。
- **原因**：服务数量有限，Compose 交付成本低，能复用 Dockerfile、健康检查和 volume；Kubernetes 留到并发和弹性需求出现后。
- **后果**：需要手工维护两台主机、备份和网络隧道；暂不具备滚动升级能力。

## ADR-002：业务层只依赖统一 Model Router

- **状态**：accepted
- **背景**：本地模型、第三方 ChatGPT 中转和规则 fallback 的延迟、成本和可用性不同。
- **决策**：业务服务只调用 `complete/embed/rerank/health` 等标准能力；provider 适配、重试、JSON repair、成本遥测集中在 Router。
- **原因**：降低供应商锁定，支持本地优先或强模型优先策略。
- **后果**：需要维护标准 schema 和 provider 兼容性；调用链多一层，但故障可解释性更好。

## ADR-003：GraphRAG MVP 使用关系表和轻量向量

- **状态**：accepted
- **背景**：完整 Neo4j/向量平台会增加挑战项目部署和调试成本。
- **决策**：以题目、技能、来源、场景和关系表实现图过滤；当前无真实 embedding 时使用确定性哈希向量，保留 PostgreSQL + pgvector 迁移边界。
- **原因**：先验证可解释链路和数据契约，不把基础设施复杂度当作产品价值。
- **后果**：召回质量低于成熟向量模型；必须通过人工评测集确认何时迁移真实 embedding。

## ADR-004：公开题目采用来源治理与转写

- **状态**：accepted
- **背景**：商业题库、公司内部面经和未声明许可的数据不能直接复制到公开仓库。
- **决策**：优先导入明确许可的公开来源；算法/系统设计题保存主题和自行转写题面；每条记录保存 URL、许可证、版本、访问时间、hash、置信度和脱敏状态。
- **后果**：不能宣称公司官方频率；题库需要定期重新核验上游许可。

## ADR-005：当前版本先做文字闭环，多模态保留接口

- **状态**：accepted
- **背景**：用户希望未来支持实时语音、视频和数字人，但挑战项目时间有限。
- **决策**：当前验收包含文字场景、算法题、追问和反馈；语音、视频、数字人只作为后续通道。
- **原因**：文字内容足以验证岗位匹配和反馈价值，媒体链路会引入显著的工程和隐私风险。
- **后果**：无法在当前版本评价语气、表情和临场感；需要在真实用户研究后决定优先级。

## ADR-006：算法题使用受限 runner，而不是模型执行

- **状态**：accepted
- **背景**：模型不能替代可信的代码执行结果；用户代码是不受信任输入。
- **决策**：服务端固定测试用例，受限 Python 进程执行；模型只负责解释思路、复杂度和修复建议；公网开放前迁移独立 runner 容器。
- **后果**：需要维护语言策略、资源限制和 runner 镜像；不能把当前挑战版沙箱直接视为生产隔离。

## ADR-007：开发 SQLite，生产 PostgreSQL

- **状态**：accepted
- **背景**：挑战开发需要零配置；多人并发、备份和跨实例部署需要更强数据库。
- **决策**：通过 `Database` 抽象兼容 SQLite 和 PostgreSQL；Compose 默认生产 PostgreSQL，测试使用临时 SQLite。
- **后果**：必须持续验证两种数据库的 SQL 兼容和迁移结果；向量字段后续使用 pgvector。

## ADR-008：匹配评分持久化为不可变快照

- **状态**：accepted
- **背景**：强模型评分有成本和延迟；同一简历/JD 组合在页面切换、刷新和重复点击时会被反复请求，且分数漂移会破坏用户信任。
- **决策**：以 `(user_id, target_key, input_hash, scoring_version)` 为唯一键把评分结果写入 `match_snapshots`；快照首写后不可变；`input_hash` 基于剥离易变元数据后的规范化档案与 JD 计算；评分逻辑变更通过提升 `scoring_version` 使旧快照自然失效。
- **原因**：把付费模型调用降到"每个输入组合一次"，同时保证相同输入分数稳定可复现。
- **后果**：档案或 JD 的语义等价变化（如字段顺序）不会触发重算；要修正历史评分必须发布新的 scoring_version，不能原地改写。

## ADR-009：群面先做 AI 模拟队友，真人匹配后置

- **状态**：accepted
- **背景**：调研记录 R-001-D 表明群面的核心难点是找到水平相近且时间重合的真人队友；但真人匹配需要等待池、隐私和缺席处理设计，超出当前交付周期。
- **决策**：当前版本以 AI 模拟队友实现群面（固定 2-3 个互补人设、自主推进节奏、发言持久化与回放）；真人匹配、可见范围和等待池作为 P1 独立设计。
- **原因**：先验证群面评分维度（问题定义、协作、共识、时间管理）和讨论交互的价值，避免在无真实用户验证前投入撮合系统。
- **后果**：当前群面不能评价真实人际动态；模拟队友发言标记为应用自有 `synthetic_mock` 内容，不得包装为真实群面数据。
