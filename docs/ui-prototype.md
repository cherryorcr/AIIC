# AIIC 前端原型与交互设计

> 本文档描述当前 `frontend/src/App.tsx` 已实现的界面结构与交互流程，作为原型图的文字化基线（低保真线框 + 交互说明）。所有区块均为 `implemented`，占位/未实现项在 §9 单独列出。视觉规范见 §8。

## 4. 面试训练工作台（核心页面）

### 4.1 布局（非算法模式）

```text
┌ 标题: "用一次短练习，校准你的回答。" [后端状态徽标] [重置] ┐
│ [技术面][算法面][行为面][压力面][案例面][科研面][HR面][群面] │
│ 模式徽章 · 第N题 · 建议用时 · 进度条▓▓▓░                    │
├──────────────────────────┬────────────────────────────────┤
│ 对话面板                  │ 反馈面板          [⇄ 交换面板]   │
│  AI: 首题（个性化标注）    │  总分徽章（均值×20 百分制）       │
│  我: 回答气泡             │  维度评分条×4（中文维度名）       │
│  AI: 追问…               │  做得好的地方 / 下一次可以更好     │
│  [模型正在分析…打字动画]   │  回答证据（原句引用）             │
│ ┌──────────────────────┐ │  下一步追问卡                    │
│ │ 作答输入区 (字数统计)   │ │  [重新回答][补充/修订]           │
│ │        [发送回答 ≥8字] │ │  [继续追问][换新题][完成训练]    │
│ └──────────────────────┘ │                                │
└──────────────────────────┴────────────────────────────────┘
```

### 4.2 一次完整训练流程

1. 选择模式 → 自动创建会话（无档案时使用默认 JD 兜底）→ AI 首题进入对话流，个性化题标注"已结合岗位 JD 和你的简历生成"。
2. 输入 ≥8 字后提交 → 打字动画 → 反馈面板亮起。
3. 反馈后四个动作：重新回答（retry）、补充/修订（supplement，预填原回答，`revision_of` 提交）、继续追问、换新题（`/advance`）。
4. 追问耗尽或用户点完成 → `/complete` → 报告落库；0 轮时明确提示"未生成训练记录"。
5. 断线自愈：turn 提交失败时先查会话摘要，若服务端已记录则恢复持久化反馈，不重复提交。

### 4.3 算法模式布局

```text
┌ 左: 题目面板              ┬ 右: 深色代码面板 (#18243a)      ┐
│  题干 · 技能chips         │  Python 3.11 · [受限沙箱🛡]     │
│  来源/license/置信度      │  行号 + 等宽 textarea 编辑器     │
│  判题约束说明             │  [运行测试]                     │
│  [换一道题][完成训练]      │  结果: N/N 通过 · Xms /          │
│                          │  timeout / rejected / failed    │
└──────────────────────────┴────────────────────────────────┘
```

- 首次运行自动以运行结果落一轮 Turn，使算法练习进入历史与报告。

### 4.4 群面特有交互

- 对话面板变为"群面讨论"：队友发言间隔选择（5/8/12 秒）、暂停/继续按钮。
- 前端定时调 `/group/advance`，AI 队友消息陆续进入讨论流（"模拟队友正在组织观点…"）；服务端 `next_delay_seconds` 可自适应放慢节奏。
- 用户可随时插话；反馈面板含"模拟队友讨论"卡（阶段 + 各队友 reaction 与下一步提示）；恢复会话时历史队友发言回放。

## 5. 岗位匹配页原型

```text
┌ 左: 已保存岗位列表        ┬ 右: 匹配详情                     ┐
│  [分数徽]岗位名·公司      │  岗位名 [用此岗位开始训练]        │
│  …                       │  综合匹配度 NN/100（评分来源标注） │
│  [上传新的 JD]           │  "为什么匹配"解释卡（快照状态）    │
│                          │  已覆盖技能 | 建议补强（→去训练）  │
│                          │  推荐题目×5（个性化/题库来源标注） │
│                          │  追溯步骤: JD解析→技能归一→训练验证│
└──────────────────────────┴────────────────────────────────┘
```

- 界面明示"评分只在简历或 JD 内容变化后重新生成"（快照机制）；无岗位时空态引导先保存真实 JD，不生成伪匹配分。

## 6. 求职资料页流程

```text
上传文件(PDF/DOCX/TXT/MD ≤5MB) → AI 提取 → 可编辑草稿表单
  → 用户人工校对 → [确认并保存到档案] → 写入 Profile / Job
                 → [删除资料]（confirm 弹窗）
```

- 表单字段：简历（姓名/方向/简介/教育/经历/技能/项目/成果）；JD（岗位/公司/方向/地点/职级/简介/技能/职责/要求）。
- 明示"强模型仅根据文件内容填充……保存前请人工核对"，AI 结果确认前不进入规范资料。

## 7. 题库 / 报告 / 账户页

- **题库**：搜索（250ms 防抖）+ 8 模式过滤 tab + 题目列表；详情面板含收藏、Rubric 勾选列表、来源区（URL/license/置信度/版本）和"加入训练"（直接建会话跳转训练页）。后端不可用时降级为内置 8 道演示题并明示。
- **报告**：四个统计卡（会话数/平均分/持久化报告/待复盘）+ 训练记录表；每行展开为逐轮对话回放（问题、回答、代码与判题结果、AI 反馈全量）。
- **账户**：临时工作区提示"注册会直接升级当前临时用户，数据保留"；注册/登录双 tab；已登录显示账户摘要与登出（登出后自动创建新临时用户）。
