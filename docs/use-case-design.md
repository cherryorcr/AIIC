# AIIC 用例设计

## 1. 用例范围

用例覆盖一个候选人从建立工作区、准备个人材料、匹配岗位、选择面试场景、完成面试训练、运行算法代码到查看报告的完整闭环，也覆盖知识库管理员和系统管理员的维护动作。

当前支持的场景 ID：`technical`、`algorithm`、`behavioral`、`stress`、`case`、`research`、`hr`、`group`。场景策略由后端 `SCENE_POLICIES` 提供，前端从 `/api/v1/scenes` 读取展示信息。

## 2. 参与者

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 候选人 | 主参与者 | 提供背景和岗位信息，选择场景，回答问题，查看反馈 |
| 临时用户 | 候选人的匿名工作区 | 不注册也可完成体验；注册后原地升级并保留数据 |
| 注册用户 | 候选人的正式工作区 | 通过邮箱密码登录，访问自己的资料、会话、收藏和报告 |
| 知识库管理员 | 支持参与者 | 导入、校验、发布和软删除题目及来源 |
| 系统管理员 | 支持参与者 | 配置模型路由、密钥、限流、部署和运行监控 |
| Model Router | 外部系统 | 统一访问本地模型网关与第三方强模型 |
| Code Sandbox | 外部系统 | 在受限进程中运行算法题代码 |

## 3. 用例关系

```text
候选人

  ├─ UC-02 注册或登录账户

  ├─ UC-04 上传并确认简历/JD

  ├─ UC-06 创建面试训练会话
  ├─ UC-07 完成文字面试与追问
  ├─ UC-08 完成算法题并运行代码
  ├─ UC-09 重答、补充或跳过当前问题
  ├─ UC-10 完成会话并查看报告
  ├─ UC-11 浏览、收藏和加入题库训练
  ├─ UC-12 查看工作区准备度与历史
  └─ UC-15 参与群面模拟讨论

知识库管理员 ── UC-13 导入/审核/发布题目与来源

UC-05 依赖 GraphRAG；UC-07 依赖场景策略、Rubric 和 Model Router；
UC-08 依赖 Code Sandbox；UC-10 依赖 Session、Turn、Feedback 持久化。
```

## 4. 详细用例

### UC-01 建立或恢复工作区

- **目标**：让用户无需注册即可开始体验，并保证每个工作区相互隔离。
- **前置条件**：浏览器可以访问后端。
- **主流程**：前端调用 `GET /api/v1/auth/me`；服务端没有有效会话时创建临时用户；服务端下发 HttpOnly 会话 Cookie；前端加载工作区概览。
- **替代流程**：后端暂时不可用时，前端显示错误和重试入口，不把用户输入伪装成已保存。
- **后置条件**：用户拥有服务端识别的 `user_id`；客户端不提交用户 ID 作为授权依据。
- **验收**：临时用户之间的资料、岗位、会话和报告不可互读。

### UC-02 注册或登录账户

- **目标**：把临时工作区升级为可长期访问的邮箱账户。
- **主流程**：用户提交显示名、邮箱和密码；服务端校验格式和唯一性；密码以 PBKDF2-SHA256 哈希保存；当前临时用户原地升级；服务端撤销旧会话并创建新会话。
- **替代流程**：邮箱已注册、密码错误或格式非法时返回明确业务错误；不泄露数据库异常细节。
- **后置条件**：登录态只保留随机令牌，数据库只保存令牌哈希。
- **当前限制**：暂未实现邮件验证、找回密码和第三方 OAuth。

### UC-03 维护个人背景

- **目标**：形成可用于技能匹配和个性化提问的用户证据。
- **输入**：技能、项目经历、教育、经验、成就、约束。
- **主流程**：用户编辑字段；前端调用 `PUT /api/v1/profile`；服务端按当前会话保存；前端保留按用户命名空间隔离的降级缓存。
- **约束**：不得把用户未提供的项目、技术或成果写入个人背景。
- **验收**：刷新页面或重新登录后数据可恢复；另一个用户不能访问该记录。

### UC-04 上传并确认简历/JD

- **目标**：把非结构化材料转为用户可以审阅的候选结构。
- **主流程**：用户上传 PDF、DOCX、TXT 或 Markdown；服务端检查扩展名、大小和文本上限；抽取文本；调用模型或本地 fallback 解析；保存 `parsed_json`；前端展示可编辑草稿；用户确认后写入 `user_profiles` 或 `jobs`。
- **替代流程**：格式不支持、文件过大、解析失败时保存失败状态，不持久化原始二进制；用户可改用手工输入。
- **验收**：AI 抽取结果必须经过用户确认才能成为规范资料。

### UC-05 预览岗位与题目匹配

- **目标**：解释当前岗位需要哪些技能，以及为什么推荐这些题。
- **主流程**：服务端读取岗位文本和用户资料；抽取并归一化技能；按场景、岗位和难度进行关系过滤；执行词法/向量召回与去重；按来源置信度排序；返回匹配技能、缺口、题目和来源。
- **输出**：`match_score`、`required_skills`、`profile_matched_skills`、`questions`、`source_confidence`。
- **替代流程**：检索无结果时使用自编或已许可基础题；不得展示虚假来源或高频标签。
- **验收**：相同岗位和资料在题库数量变化时，匹配分数仍按技能覆盖计算，不因题目数量波动。

### UC-06 创建面试训练会话

- **目标**：创建带场景策略、岗位、用户资料和首题的 Session。
- **主流程**：用户选择场景和难度；前端调用 `POST /api/v1/sessions`；服务端执行匹配；Model Router 生成或润色首题；服务端保存 Session；返回当前题目、匹配理由和来源。
- **替代流程**：模型超时则使用题库原题；题库无可用题时返回可理解的错误，不创建半成品训练记录。
- **后置条件**：Session 状态为 `questioning`，当前题目已持久化。

### UC-07 完成文字面试与追问

- **目标**：按照场景 Rubric 对回答评分并推进状态。
- **主流程**：用户提交回答；服务端保存 Turn；加载当前场景维度；Model Router 请求结构化评分；校验 JSON；保存 Feedback；按弱项生成追问或下一题；返回反馈卡片。
- **场景差异**：技术面评价正确性、复杂度、取舍、排障；行为面评价 STAR、个人贡献、证据和复盘；压力面评价稳定性、简洁性和应变；案例面评价拆解、指标、假设和验证；科研面评价假设、实验、局限和批判性思维；HR 面评价动机、匹配、沟通和真实性；群面增加阶段和模拟队友反应。
- **硬约束**：`evidence_quotes` 只能引用用户原回答；缺失证据必须明确标记。
- **替代流程**：模型不可用时使用确定性 fallback；模型返回非法 JSON 时尝试一次修复，仍失败则返回规则反馈。

### UC-08 完成算法题并运行代码

- **目标**：让用户同时练习解题思路、复杂度表达和代码正确性。
- **主流程**：用户查看题目和约束；提交 Python 代码与测试；服务端进行 AST 策略检查；在临时目录启动受限子进程；返回通过数、错误、耗时和安全摘要；再由 Evaluator 结合运行结果反馈。
- **安全约束**：禁止网络、危险模块、反射逃逸、宿主目录访问和无限输出；限制 wall timeout、CPU、内存、进程数、文件大小和文件描述符。
- **替代流程**：禁用沙箱、代码违规、超时、运行异常分别返回 `disabled`、`rejected`、`timeout`、`error`。
- **当前范围**：仅支持 Python；生产开放前应迁移到独立 runner 容器或更强隔离设施。

### UC-09 重答、补充或跳过当前问题

- **目标**：允许用户根据反馈改善回答，而不破坏原训练轨迹。
- **重答**：提交 `revision_of` 指向已有 Turn；服务端使用原问题 Rubric 重新评分，不推进会话游标。
- **补充**：以 `answer_mode=supplement` 提交新增证据，继续当前问题上下文。
- **跳过**：前端切换到下一题；未回答的草稿不计入训练报告。
- **验收**：重复提交同一题在已持久化反馈后返回幂等结果，不重复推进两次。

### UC-10 完成会话并查看报告

- **目标**：保存本轮训练结果并提供下一步建议。
- **主流程**：用户点击结束；服务端将 Session 标记为 `completed`；有回答时生成报告快照；前端读取会话摘要、分项分数、平均分、证据和改进建议。
- **替代流程**：没有任何回答时只结束草稿，不生成零分报告。
- **验收**：未完成维度显示“无数据”，不填充虚假分数。

### UC-11 浏览、收藏和加入题库训练

- **目标**：让用户查看公开题库并把题目加入训练队列。
- **主流程**：前端调用 `GET /api/v1/questions`；按场景、关键词和技能过滤；打开题目详情；收藏通过 `POST /api/v1/questions/{id}/favorite` 持久化；加入训练后创建对应 Session。
- **约束**：题库界面展示来源类型、URL、许可证、版本和置信度；不得把转写题包装为官方题或频率统计。

### UC-12 查看工作区准备度与历史

- **目标**：聚合技能覆盖、训练次数、报告和最近会话。
- **主流程**：前端调用 `GET /api/v1/workspace/overview`、`/history` 和 `/reports`；服务端只查询当前用户资源；前端展示准备度、技能缺口和历史结果。
- **验收**：用户注销并切换账户后，前端缓存命名空间和服务端数据均不串户。

### UC-15 参与群面模拟讨论

- **目标**：在没有真人队友时，让用户与 AI 模拟队友完成一场群面讨论并获得针对性反馈。
- **前置条件**：用户以 `mode=group` 创建会话。
- **主流程**：系统给出讨论议题；用户发言后，评分反馈附带讨论阶段（`group_phase`）和 2-3 位固定人设模拟队友（推进者、质疑者、数据派）的反应；用户不发言时，前端按可调间隔（5/8/12 秒）调用 `POST /sessions/{id}/group/advance`，服务端生成一条队友自主发言（禁止同一队友连续发言）并持久化到 `group_messages`；服务端可返回 `next_delay_seconds`（4-20 秒）主动调节节奏。
- **替代流程**：用户可暂停/恢复队友讨论、随时插话或调用 `/advance` 换议题；模型不可用时使用确定性队友发言兜底；恢复会话时历史队友发言按时间线回放。
- **评分维度**：problem_framing、collaboration、consensus、time_management。
- **当前限制**：队友为 AI 模拟（题目标记 `synthetic_mock` 自有内容），真人群面匹配（能力/时间/可见范围约束）为 P1 规划，见 Product Memo。

### UC-13 导入、审核和发布题目与来源

- **目标**：维护可追溯的 GraphRAG 知识库。
- **主流程**：管理员验证数据文件；登记来源；按 `content_hash` 去重；导入题目、技能、关系和 Rubric；质量校验通过后发布索引版本。
- **替代流程**：许可证缺失、URL 缺失、PII 未脱敏的数据进入隔离区；删除采用软删除。
- **接口**：`/api/v1/admin/knowledge/*`，生产环境需要 `X-Admin-Token`。

### UC-14 配置模型路由和查看健康状态

- **目标**：在本地模型、第三方模型和确定性 fallback 之间稳定切换。
- **主流程**：管理员配置环境变量；Model Router 按任务选择 provider；记录 request、model、延迟、tokens、成本和 fallback；通过 `/api/v1/model/health` 查看状态。
- **约束**：密钥不进浏览器、Git、普通日志或数据库；业务代码不直接耦合供应商协议。
- **替代流程**：强模型超时或 401 时切换本地网关，再切换规则模式；页面仍可打开并提示降级。

## 5. 跨用例规则

- 所有资源读取和修改都基于服务端会话推导用户，不信任请求体中的用户 ID。
- 所有 AI 生成结果都必须经过 schema 校验或 fallback 归一化。
- 所有外部题目都必须带来源和许可元数据；模拟题目必须标记 `synthetic_mock`。
- 多模态、语音、视频和数字人只保留扩展接口，不属于当前用例验收范围。
